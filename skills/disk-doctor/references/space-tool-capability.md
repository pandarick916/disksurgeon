## 方法说明（为什么没做反汇编）

原计划用 `morluto/rea` 的 native 工作流（`open_binary` + `trace_native_values`）逆向可执行文件。**实际没有做，理由如下：**

1. **目标不是复刻实现，是复刻能力。** 它的核心算法是公开的 squarified treemap（Bruls/Huizing/van Wijk, 2000），不需要从二进制里挖。
2. **官方手册是更高等级的证据。** 30 页手册逐条说明功能与行为，比 strings/反汇编推断的置信度高得多。
3. **成本极不对称。** 反汇编能拿到的增量（内部数据结构、扫描线程调度细节）对"重造一个更好用的诊断器"没有帮助。

> 这是"证据驱动"而非"工具驱动"：**先问需要什么证据，再选证据来源**，不是拿到锤子就找钉子。
> 若后续需要复刻它的**具体视觉参数**（色板、圆角、字体、动画曲线），那时才值得上运行时观察（截图取样 + 像素量测）。

## 刻意不做的，以及理由

| 能力 | 为什么不复刻 |
|---|---|
| 标签 / 实时监视 / 局部扫描 / ADS | 都是**桌面长驻软件**才成立的交互。我们交付的是"一次性诊断报告"，用户看完就去处理，不需要常驻 |
| 右键资源管理器菜单 | 浏览器安全模型不允许；真需要时由专家给出路径，让系统自己去点 |
| 交互式复杂过滤 | 小白友好优先：`--min-size` 一个旋钮 + 一眼可读的颜色分级，比一排过滤器更有效。**过滤是专家的事，不是小白的事** |

---

## 我们比它强的地方

1. **零安装**。它是 exe（要下载、要看杀软脸色），我们是**一个 HTML 文件**，双击就开，能微信发人。
2. **一次生成，永久可查**。快照是静态文件，回头还能对比两个时间点。
3. **颜色即结论**。它让你自己判断谁大；我们直接用红/橙/蓝标出"该处理 / 该看 / 正常"，小白不用学。
4. **诊断接搬家**。它只能告诉你"这里大"，我们下一步能直接把那个目录搬走（junction），形成闭环。**这是它作为通用工具做不到的。**
