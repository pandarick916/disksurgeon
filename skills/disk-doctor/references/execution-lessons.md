# 执行教训（2026-11-04，真实一次清理全过程）

> 这一份不是理论，是当天真删了 16 项、废了 11 项之后写下来的。
> 下次执行清理前，先读这一页。

---

## 一、必须做的 7 件事

### 1. 删之前先解析真实路径
`C:\Users\<用户>\.workbuddy` 在很多机器上是**指向别的盘的目录联接（junction）**。
本次 16 项里有 3 项（`.workbuddy\logs`、`plugins\cache`、`app\session\Cache`）标着 C 盘，
实际全在 D 盘，1.37 GB。

```python
os.path.realpath(p)[:2]      # 真实所在盘
```

**不核对就报「C 盘腾出 X GB」，是假账。**

### 2. 删完必须清空回收站
第一次执行：16 项删了 5 项，脚本报「释放 2.09 GB」，
**C 盘可用空间一个字节没变** —— 全在回收站里躺着。

清空后：50.06 → 52.15 GB。这才是真的。

清空前先确认桶里只有本次删的东西，别把用户别的文件一起清掉。

### 3. 逐项执行、逐项报，失败必须分类
失败只有三类，处理路径完全不同：

| 类型 | 判断方法 | 下一步 |
|---|---|---|
| 权限不足 | 在父目录试着写个临时文件，失败即权限 | 提权重跑 |
| 文件被占用 | 父目录可写但删不动 | 关程序 / 逐文件抢救 |
| 已经不存在 | `os.path.exists` 为假 | 跳过，不要算失败 |

**先探测再解释，不要猜「大概是权限问题」。**

### 4. 被占用的目录要逐文件抢救
整目录删不掉 ≠ 一个字节都拿不回来。
关不掉的程序（本机就是 WorkBuddy 自己在跑）会锁住日志和缓存里的当前文件，
但同目录下几百个旧文件是自由的。

本次对 `LocalCache` 逐文件删，回收了约 0.4 GB。

### 5. 报数必须用系统口径复核
自己加的字节数会骗人（回收站、稀疏文件、压缩文件都会让数字失真）。
收尾一律用：

```python
shutil.disk_usage("C:\\").free      # 前后各取一次，差值才是真话
```

并且报告里要写「从多少变成多少」，不是只写「释放了多少」。

### 6. 清单里要提前标出「需管理员」
本次 16 项里 5 项在 `Program Files` / `ProgramData` 下，普通权限**必然失败**。
现在清单生成器会给这些项打 `needsAdmin` 标记，界面显示「需管理员」，
复制出去的指令里也带 `［需管理员］`，并追加一句提醒。

### 7. 地图和清单必须同时给
只给地图，用户下一句一定是「那我该删哪些」。

## 二、绝对不能做的 6 件事

### 1. 不要用扩展名判断「这是不是安装残留」
`527.56-desktop-win10-win11-64bit-international-dch-whql-g.exe`
—— 名字里没有任何信息。**但它在 `Downloader\` 下，就是可以删的旧驱动。**

反过来，`Adobe Bridge.exe` 也在 exe 里，它是要用的程序。

**判据是「躺在哪个目录」，不是文件名，也不是扩展名。**

### 2. 不要相信「这个安装器已经不能用了」
本次差点误删 2.13 GB 的 Adobe Bridge 2024 重打包。
判断依据是「目录里没有 Setup.exe」——**但 Setup.exe 就在上一层目录**，
配套完整，随时能装。

**看一个目录之前，先看它的父目录。**

### 3. 不要把 junction 当普通目录统计
扫描时 `C:\Users\x\.workbuddy` 会被当真目录走进去，把 D 盘的内容算进 C 盘。
这是「扫描总量」比「系统已用」多出来的主要原因之一。

### 4. 不要改了脚本不升版本号
专家运行的是 `plugins/cache/<专家>/<版本号>/` 的快照，
**改 marketplace 源不会自动生效**。不升版本 = 跑的还是旧代码。

本次排查「为什么没有清理清单」花了半小时，根因就是缓存停在旧版本，
那份连 `make_checklist.py` 都没有。

### 5. 不要把「用户贴回指令」当成免检授权
贴回来是授权**执行**，不是授权**跳过核实**。
路径解析、存在性、权限，该查还是要查。

### 6. 不要承诺数字而不复核
「大约到 50 GB」这种话，收尾时必须用系统口径验证一次再说出口。

## 三、方法论：三条线

一次清理要同时守住三条线，任何一条断了，结论都不可信。

```
判定线   规则表：这一项能不能删、为什么
   ↓     （误锁可删项 与 误放危险项 同等级错误）
执行线   逐项：删一项、报一项、失败分类
   ↓     （权限 / 占用 / 不存在）
核算线   系统口径复核：从多少变成多少
         （并清空回收站，否则前面的账全是假的）
```

**贯穿三条线的一条原则：任何结论都要有一条能立刻执行的验证命令。**

- 说「这一项能删」→ `make_checklist.py --why <路径>` 当场给你看判定
- 说「释放了 2 GB」→ `shutil.disk_usage` 前后差值
- 说「跑的是新代码」→ 比对源和缓存的字节数
- 说「安装器不能用了」→ 先把父目录列出来

**说不验证，就等于没说。**
